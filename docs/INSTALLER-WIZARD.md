# 安装、更新与恢复怎样衔接

向导把组件选择、下载、校验、准备、插件事务和配置保存放进同一窗口。选择组件后先检查已有文件与缓存，显示净下载量；用户确认后顺序执行，不在每个阶段重新弹出确认。

## 稳定数据与可替换程序

已有 `LilithBridge.data-dir.txt` 继续指向原数据目录。新安装使用游戏目录中的 `LilithBridgeData`，不按游戏版本或插件版本新建配置。Key、记忆和索引保持原位；普通插件更新完全不改写配置，未知字段也不会丢失。

Python 与依赖使用本机用户目录下 LilithBridge 自己的短路径，避免深层游戏目录触发 Windows 路径长度限制。它们不注册成系统 Python，也不修改 PATH。模型与 worker 采用固定身份；健康的现有路径优先复用。模型目录只有清单中的 11 个文件，下载状态与临时文件放在模型目录之外。

本地召回准备完成后，先检查最终 Python、worker 与模型，使用独立临时索引和合成短文本验证，再把最终路径和启用状态一次原子保存。准备失败时不会切换旧配置。已有 Key、未知配置字段和自定义索引目录保留。

## 下载来源

- 插件默认使用包内已验证版本；也可从固定仓库 `gtxpz2021/LilithBridge` 的公开 Release 读取发行与资产元数据。仅接受仓库自己的安装 ZIP、受限名称、大小及 GitHub SHA-256，随后校验 ZIP 内插件清单与 DLL。不会运行远端清单里的命令或任意 URL。
- BepInEx 固定官方 be.769 ZIP；存在不同文件时保留并停止，不覆盖其他加载环境。
- Python 使用官方 NuGet `python/3.12.10` 完整发行包，正常建立 venv，不把 embeddable 包改造成 pip 环境。
- 34 项 CPU wheel 逐项锁定来源、大小和 SHA-256。BGE-small-zh-v1.5 固定 revision `7999e1d3359715c523056ef9478215996d62a620`，只取清单 11 项，不克隆全仓库。

下载保持正常 HTTPS 证书验证。缓存命中先校验；损坏的本机缓存隔离后重取。下载 `.part` 可按服务器 Range 支持续接，服务器返回完整文件时重新写入；最终大小和摘要必须一致。模型下载状态不进入模型目录。断网、证书或代理失败不会伪装成完成。

## 游戏更新与项目更新

游戏版本与摘要是诊断材料。当前依赖的类型、成员和签名仍满足时，可以继续使用；仅生成关联变化不会直接判为不兼容。生成物缺失、无法读取或确有旧接口缺失时，才等待游戏的加载器重新生成。接口检查不代表能自动修补任意未来 ABI，也不代替实际游戏行为验证。

“检查项目更新”仅在用户点击时联网，包含当前预览通道的公开发行。未来发布的插件摘要不必预埋在旧安装器中。下载后用现有事务备份、替换与回读；游戏运行时等待正常退出，窗口关闭后保留下载与不含秘密的组件会话，下次继续。不会强杀游戏、创建常驻服务或计划任务。

本候选不覆盖正在运行的 EXE。远端清单确实需要新版安装器或配置 schema 时，经完整包校验及受支持的交接协议，辅助程序等旧窗口退出后，在新目录启动固定入口并恢复无 Key 会话；协议或能力不符时停止。普通插件更新不强迫安装器自更，详见 HANDOFF-PROTOCOL.md。

## 取消与恢复

下载可立即取消；Python 安装会结束当前有界操作后停止，避免留下仍在写文件的 pip 子进程。成功插件不会因为可选模型失败而自动回退。中断后重新检查实际文件并复用已完成项；未完成的自有 venv 可在再次准备时由原安装脚本清理重建，已核验 wheel 缓存保留。

插件恢复与回退复用原事务，只处理 LilithBridge 自有文件；共享加载器、配置、模型、记忆和存档不在删除清单内。API Key 不进入会话、下载记录、命令行或包内证据；未保存的 Key 关闭后不保留。


已确认的使用范围及在线下载等限制见[当前验证范围](../CANDIDATE-VALIDATION.md)。下载遇到问题时，可运行安装包根目录的 `Network-Diagnostic.cmd`，完成一次无 Key 自检。
